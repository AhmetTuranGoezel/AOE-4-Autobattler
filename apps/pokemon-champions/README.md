# Pokémon Champions · Stat Lab

A fast filter/sort tool for the **Pokémon Champions** competitive roster. Headline
feature: a **cleaned / effective stat total** that strips out stats a Pokémon can't
actually use (Sp.Atk on a pure physical attacker, Speed on a mon that's too slow to
matter), so you compare what each mon *really* brings.

Three tabs:
- **Pokémon** — the roster table/grid with all the filtering, sorting, radar charts,
  cleaned stats and find-similar.
- **Moves** — every move in the roster's movepools with power / accuracy / PP / priority,
  competitive **flags** (Contact, Slicing, Bomb/Ball, Punch, Bite, Sound, Powder…),
  effect text, and how many Pokémon learn it. Click a move to filter the roster by it.
- **Abilities** — every ability with description, how many Pokémon have it, and a sprite
  preview. Click to filter the roster.

Also: type / role / generation / Mega filters, ability & move quick-search with **rarity**
badges, stat-range filters, a **radar chart** (base vs cleaned overlay), and
**find-similar**. All client-side and instant.

## Run
Served statically (no build step). From the repo root:

```
python -m http.server 8000
# open http://localhost:8000/apps/pokemon-champions/
```

ES modules + `fetch` need http(s), so open it through a server, not `file://`.

## Data
`champions-data.json` is a committed, pre-built snapshot. It is generated by
`tools/generate_data.py`:

- **Regulation** is configured in [`tools/regulation.json`](tools/regulation.json),
  including the official announcement URL and start/end dates. The generator
  copies it to `meta.regulation` / `meta.regulationDetails` in the snapshot. The
  header shows this on desktop and mobile and links to the official rules.
  This is an explicitly maintained snapshot label, not automatic regulation detection.
- **Roster / availability** is scraped from Bulbapedia's *List of Pokémon in
  Pokémon Champions* via the MediaWiki API. This lists available/game-data forms,
  **not an official ranked eligibility whitelist**. Check the linked regulation
  announcement for eligible Pokémon and Mega Evolutions.
- **Per-Pokémon movepools** first use the existing
  [Champions community dataset](https://github.com/otterlyclueless/pokemon-champions-data).
  Only exact-form records with `championsVerified: true` and
  `source: "serebii-champions"` qualify. Missing/unverified records, ambiguous
  form unions, and the upstream Psychic omission are checked against the
  original [Serebii Champions Pokédex](https://www.serebii.net/pokedex-champions/).
  Its parser selects the form's move table, including Rotom's form-only moves;
  it does not merge every form on a species page.
- **Unverified learnsets** have `learnset.status: "unverified"` and `moves: []`.
  This means *unknown*, not that the Pokémon learns no moves. Generic PokéAPI
  and broader PokéBase lists are diagnostic candidates only: they never become
  selectable/legal moves, learner counts, or coverage recommendations. Saved
  moves still present in the move dictionary but no longer confirmed for their
  Pokémon are flagged and excluded from team analysis, not silently counted.
- **Learnset provenance** is stored per Pokémon (`learnset.status`, `source`,
  and, where verified, `url` / `entry`). [`learnset-report.json`](learnset-report.json)
  lists every source, unresolved Pokémon, withheld candidates and usage moves
  not confirmed by the learnset. “Verified” describes source evidence, not
  official certification or a guarantee that community data has no errors.
- **Stats, types, abilities, sprites, and per-move metadata** (power/PP/accuracy/effect)
  come from [PokéAPI](https://pokeapi.co).
- **Move flags** (Contact, Slicing, etc., which PokéAPI lacks) are merged from
  [Pokémon Showdown](https://play.pokemonshowdown.com/data/moves.json).
- **Champions move/ability metadata and usage** also use PokéBase; precise
  descriptions use the community dataset. Usage can still refer to an earlier
  format/tournament sample even when freshly fetched; it is not proof of move
  legality or current-regulation ladder usage.
- **Derived fields** (offensive bias, ability/move rarity) are computed in the script
  over the real Champions movepools.

### Refresh after a balance patch / new regulation

For a new regulation, first update **only `tools/regulation.json`** with the
official identifier, announcement URL and UTC dates. Do not infer a regulation
from a generic roster page or rename an old snapshot without regenerating it.
Then, from the repo root:

```
python apps/pokemon-champions/tools/generate_data.py --refresh
python apps/pokemon-champions/tools/generate_items.py --refresh
```

Requires Python 3.9+ (stdlib only). All HTTP caches live under
`tools/.cache/v2/<regulation>/` and expire after **24 hours**. A regulation change
automatically selects a fresh namespace; old unscoped cache files are ignored.
`--refresh` bypasses every source's cache immediately (also use it for balance
patches). Repeated requests within that same run reuse newly fetched responses.
Running without the flag is useful for quick reruns/resuming a failed generation;
it can reuse same-regulation responses younger than 24 hours. Failed network
refreshes abort instead of quietly substituting expired data. No manual cache
deletion is needed. Four bounded workers keep a full refresh practical.

Review the printed warnings and `learnset-report.json` before committing the
snapshot. Optional `--strict-learnsets` writes the diagnostic report and exits
unsuccessfully without replacing the snapshot if any learnsets remain unverified.
Ordinary generation publishes those Pokémon with moves withheld and visible warnings.

If “slugs not found on PokeAPI” appear, fix `tools/roster_overrides.json`:
`_remap` normalizes roster names, `_skip` excludes redundant cosmetic forms, and
`_api` changes only the API lookup while preserving an existing app slug.
Review `meta.skippedRosterEntries`; missing entries must not be mistaken for a
complete roster. Commit the snapshot, report, configuration and any changes to
`tools/move_ids.json` together. Move IDs are append-only; never renumber/delete
existing mappings because saved teams and share codes reference them.

The Pyroar regression was a missing community record combined with the remapped
`pyroar-male` PokéBase page's broader 70-move list. Both Pyroar forms now use the
49-move Champions table, without a hardcoded species-specific move list. The
same source selection and reporting apply to the entire roster.

### Table ranks

`Rank` is the position in the **complete filtered and sorted** result (1–N), not
the Pokédex number or a viability score. It is not sortable. Pins inside that
result retain their rank when displayed at the top; pins outside the filters
show `—` and do not consume a rank. The result count and summary describe the
filtered result, including matching pins, not unrelated pinned comparisons.


The Python tests use offline fixtures and mocked HTTP, covering cache isolation,
expiry/refresh, failure behavior, source verification, form separation and the
Pyroar fallback. Browser smoke checks can additionally be run with
`python tools/browser-smoke.py` from this app directory (requires an existing
Python Playwright installation and Chrome; no project dependency is added).

## Held items

The shared catalogue in `src/item-catalog.js` is generated from Serebii's
Champions item list, with the same regulation configuration/cache policy as
the Pokémon snapshot. Refresh **both** generators after a regulation update.
It lists held items, berries and Mega Stones, not training coupons/roster tickets.
Availability is a sourced snapshot, not a blanket guarantee of tournament legality.

`src/item-model.js` supplies shared mechanics, selectors and support notes for
Damage, Moves and Team. New source items stay selectable with an explicit
unmodeled-effect notice until their mechanics are implemented. Never add a
generic damage multiplier merely because an item can be selected.

See [ITEMS.md](ITEMS.md) for exactly which effects and app surfaces are modeled,
which are informational only, and the remaining calculation limits. Team share
links now use v4 to retain items; old v1/v2/v3 links still import. Moves keeps
one-click comparison presets: **Type item ×1.2** applies a matching booster to
every move, and **Band / Glasses** picks the appropriate category booster.
Leek and Light Ball have shortcuts for their eligible Pokémon; individual held
items are under **Custom item**, without Mega Stone clutter. Team retains its
full item catalogue. Mega forms reserve their item slot for
their stone and cannot gain an extra offensive item boost.

## Cleaned-stat model
Computed in `src/effective-stats.js`; the two toggles in the filter rail's **Cleaned
stats** section re-rank the whole list live (no data refresh):

- **Lower attack stat wasted** (default on): whichever of Attack / Sp.Atk is lower
  counts as 0 — you attack with one side.
- **Low Speed wasted** (default on): Speed at or below the cap (default 60) counts as 0.
- HP / Def / Sp.Def always count fully.
