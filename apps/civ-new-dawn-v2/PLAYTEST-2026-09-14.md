# Production recovery and interaction corrections — 2026-09-14

Work started from `56ea065` on `main`. Scope: `apps/civ-new-dawn-v2` only.
No branch, reset, rebase, push, or Pokémon edits/staging.

## Findings and fixes

### Oversized backups

Two compounding implementation defects were present:

1. `ensureMapHexes` added placement margin to the **existing allocated radius**.
   Repeated placements grew empty map storage even when their coordinates already
   fitted inside the map. Margin is now measured from the requested coordinates;
   existing cells are preserved.
2. `backupPayload` included `turnUndo.snapshot`, duplicating the gameplay state
   inside each checkpoint. Checkpoints now contain one canonical state. Turn-start
   recovery and revision history are separate records.

`Game.checkpointState` also encodes repeated hex fields using columns/templates.
`Game.unpackCheckpoint` restores the original map properties and independent
mutable objects. It rejects malformed indices, unsafe keys and duplicate cells
without partially installing a map. This is a storage encoding, not a change to
map rules or player projections. Save schema remains 2; old unencoded saves load.
The 1 MiB limit has not changed.

The final five-sample late-game size gate measured a maximum **184,656 bytes**
for the serialized HTTP body, leaving **863,920 bytes** below 1 MiB. This includes
the operation/auth envelope, canonical state and 512 maximum-length action IDs.
Fixtures complete five-player setup, expand the map with remaining physical
tiles, populate cities/control/districts/figures and retain 500 log entries plus
100 chat messages. The gate requires at least 256 KiB of headroom, not just a
barely passing payload. Samples use shuffled setups, so byte counts vary by run.

### Reconnect returning a running game to setup

The old backup-error path returned `accepted_unbacked`: it advanced the live and
local revision despite failed remote storage. Host reload then adopted the older
remote state without checking for regression. If that remote checkpoint was
still setup, capital placement became available again; re-stamping that tile
could overwrite its later contents.

There are now no locally accepted, unconfirmed online revisions. Failure keeps
the confirmed head and displays the backup error. Host recovery refuses an older
remote revision or a playing-to-setup transition. A client also refuses a setup
snapshot after entering play. Returning clients reclaim the same authenticated
seat; they do not add a new player or recreate the board.

The original playtest's raw failing checkpoint was not supplied. This identifies
the unsafe code path and tests its boundaries; it does not claim to have replayed
that exact historical packet trace.

### Lost requests, lost ACKs and local disk failure

Previously a healthy connection that still answered pings could leave a lost
action waiting indefinitely. Pending client actions now retry every two seconds
with the **same action ID and original base revision**. Reconnect owns its own
timer; ACK, cancellation and session replacement clear the action timer.

The host deduplicates committed IDs, rejects stale actions and resynchronizes.
Only accepted IDs enter persisted dedupe history. A lost backend ACK is checked
against durable status before reporting the result. If that action was committed,
a subsequent failed local write cannot turn it into a rejected action; the local
history warning is separate from remote durability.

### Science and other first-click previews

The focus-card click handler explicitly called `startAction()` whenever the
selected card held no trade. For Science this dispatched `PLAY_SCIENCE` immediately.
That shortcut is removed for every focus type. First click selects the actual
physical card; **Start Action** begins resolution. Preview selection can be
changed before starting, but not during an ACK or active resolution. Changing
previews clears uncommitted trade selections.

Older Astronomy and movement browser tests were updated to press Start Action.
The shared click helper now refuses visually disabled controls, and the new
tests verify the selected card's identity rather than only its UI phase.

### Culture count and mountains

Normal Early Empire I, no trade and no modifier, produces exactly **two** markers
in both the engine and real UI. A third target cannot place a third token.
One spent Culture trade adds one; France adds 0/1/2/3 according to its latest-era
wonder. Preview now explains those terms, for example `2 base + 1 Culture trade`.
Calculations receive the selected physical card index.

The specific reported unexplained third marker was **not reproduced** on the
normal fixture. Legitimate bonuses and stale preview changes are separately
tested; a saved affected position is still needed to identify that occurrence.

An empty mountain next to a friendly city is selectable at effective slot 5,
and not at slot 4. Drama and Poetry's subsequent move is separately tested:
it can move onto an adjacent empty mountain outside city adjacency even from
slot 1, because that printed move is not an ordinary Culture placement.

### Grand Mesa transcription

Internal tile `11`, face A, corresponds to printed **04A**. The actual repository
artwork (`assets/tts-web/map-tiles/individual/tile-04-side-a.webp`) shows the two
mountains beside Grand Mesa at cells **7 and 9**, not 7 and 8. Corrected only
**cell 9: desert → mountain**. Cell 8 remains desert. Grand Mesa remains at cell
6, typeless and difficulty 5 while its natural-wonder token is present. Browser
hover tests verify `Mountain (diff 5)` on both adjacent mountain cells.

### Setup and victory

Capital setup has three action buttons: Rotate left, Rotate right and Flip side.
Board clicks place the tile. Waiting players have no placement buttons; fortress
placement has no redundant mode controls. Capital faces and civilization
reference information remain available under collapsible details during fortress
placement. The removed private planning mode is not silently retained in tests.

Removed `computeScore`, `CFG.maxRounds` and the highest-score fallback, including
normal player/game-over score displays. Victory-card progress remains. Agenda
refresh does not end the game mid-round. Existing four-of-five, end-of-round
victory and agenda/wonder/friendly-space tiebreak behavior remains; a regression
checks that round 100 does not invent a score victory.

## Recovery architecture and boundaries

- One canonical state per local or remote checkpoint; no embedded recovery state.
- Five rotating normal cache checkpoints, **24 separately checksummed host
  revision records**, and two separate turn-start records in existing local
  session storage. History is not transmitted to guest views.
- Recover Game lists revision, round, player, phase, last action and timestamp.
  Host confirmation restores through the ordinary authoritative transaction/CAS
  path, producing a new head and incremented recovery generation. The current
  turn-start recovery option remains available after hidden information.
- Old drafts, selections, animations and presence are invalidated on recovery.
  Transport credentials and current dedupe/revision authority are not replaced
  by historical values. Late actions retain their old base revision.
- A running game cannot be restored into setup, even through host history.

**Limits:** History selection and private turn-start recovery currently depend on
the host device's storage. Netlify already stores immutable revisions internally,
but its API exposes only the current head; retrieving old revisions or separate
turn snapshots after loss of the host device needs an endpoint change outside
this app-only scope. No Netlify implementation files were modified.

A legacy session whose local head is already ahead of its remote backup is
refused rather than silently rolled back. This batch does not automatically
repair that pre-existing fork. Lost pieces for which no surviving checkpoint
exists cannot be reconstructed. Existing placed Grand Mesa terrain is not
silently rewritten by migration (which could overwrite a host correction).
No readiness gate was added. No production deployment was performed.
